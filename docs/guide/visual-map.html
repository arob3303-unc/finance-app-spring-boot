The request path

Seven hops down, seven back. Each boundary changes the representation of the data — that is the only reason the layers exist.

What each layer is allowed to know

The test of a clean boundary is what a layer does not know
LayerKnows aboutMust not know about
@RestControllerstatus codes, JSON, headers, URLsSQL, why a transfer is refused
@Servicebusiness rules, transaction boundariesHTTP, JSON, status codes
JpaRepositoryqueries and entitiesbusiness rules
@Entitythe shape of a table roweverything else

If you can describe the service layer without saying “HTTP”, “JSON”, or “status code”, the boundary is intact.

Verbs and status codes

Idempotent means sending it twice leaves the system in the same state as sending it once. It is a promise the verb makes to every client, proxy and retry mechanism on the internet — not a description of your code.

Accounts — a conventional resource
VerbPathIdempotentSuccessNotes
GET/api/v1/accounts yes200Paginated. Never unbounded.
GET/api/v1/accounts/{id} yes200 · 404404 when it does not exist.
POST/api/v1/accounts no201Returns a Location header.
PUT/api/v1/accounts/{id} yes200Full replacement of the resource.
PATCH/api/v1/accounts/{id}/status yes200One field, not the whole object.
DELETE/api/v1/accounts/{id} yes204Closes the account. The row stays.
Transfers — where the conventions break on purpose
VerbPathIdempotentSuccessNotes
POST/api/v1/transfers no201 · 409 409 on insufficient funds. Needs an Idempotency-Key header so a retry cannot double-charge.
GET/api/v1/accounts/{id}/transactions yes200Paginated statement.
POST/api/v1/transfers/{id}/reversal no201 The only way to undo money movement.
PUT/api/v1/transfers/{id} —never A posted transfer is history. History is not editable.
DELETE/api/v1/transfers/{id} —never Deleting money movement destroys the audit trail. Post a reversal.

The double-entry ledger

No table stores a balance. A balance is SUM(amount) over an append-only ledger, which means it can always be recomputed and always be proved.

Money is never a double

double cannot represent 0.10 exactly, so 0.1 + 0.2 is 0.30000000000000004. Across a million transactions that error compounds into money that does not exist.

Use BigDecimal in Java against NUMERIC(19,4) in Postgres, and compare with compareTo — never equals, which calls 2.0 and 2.00 different values.

Atomicity

A transfer is two writes. The entire discipline of a financial system is making sure that either both land or neither does.

Three ways @Transactional silently does nothing

Self-invocation. Spring implements it with a proxy that wraps the bean. Calling an annotated method from another method of the same class bypasses the proxy, so no transaction starts.

Checked exceptions. Rollback happens on RuntimeException and Error by default. Throw a checked exception and the transaction commits. Use @Transactional(rollbackFor = …) when you need otherwise.

Private or non-public methods. The proxy cannot intercept them. The annotation is ignored, with no warning.

Boot 4 breaks most tutorials you will find

Auto-configuration was split into per-integration modules, so a library on the classpath is no longer enough. Adding flyway-core alone produced no error and no log output — Flyway simply never ran until spring-boot-flyway was added too. Same reason your project uses spring-boot-starter-webmvc rather than the spring-boot-starter-web every guide shows.

Also gone: WebSecurityConfigurerAdapter and antMatchers(). And springdoc 2.8.x targets Boot 3 — Boot 4 needs the 3.x line, pinned by hand because Boot does not manage its version.

When a Spring feature does nothing at all, suspect a missing auto-configuration module before suspecting your own code. No output is a different symptom from wrong output.
